# Working in this repository

This is a research repository, not a library. A change here is a claim about
what was measured, so the rules below are about evidence and provenance rather
than about code style.

## Where work belongs

This repository holds measurement: experiments, their data, their figures, and
the prose that grades them. Three kinds of work do **not** belong here.

- **Runtime changes and upstream pull requests** go to the `omlx` fork. Nothing
  in this repository patches the inference server. When a finding produces a
  pull request, this repository records its number and its state, and says it is
  open at the time of writing until that stops being true.
- **The portfolio narrative** lives on `meowcoder.com`, which summarizes the
  whole program for a reader who has not decided whether to open the data.
- **Long-form articles** are published on `study.meowcoder.com`. Where an
  article and this repository disagree, the files here are correct, and each
  experiment README says so.

All three link back here, and this repository links out to all three. A result
is not finished until every one of those edges exists in both directions.

**A number that leaves this repository carries its source with it.** The
article, the portfolio page and a pull request body all restate numbers that
live in `data/`. Changing one here changes them there in the same commit, not
as a follow-up. Quote a row only after reading its entry in `data/README.md`,
which is where the aggregation and the evidence level are written down.

## Evidence discipline

`EVIDENCE.md` is the ladder. Every claim in a findings document carries a label,
and the labels mean different things:

- **Observed** — the runtime reported it.
- **Measured** — it came from a matched pair.
- **Derived** — arithmetic over measured numbers.
- **Inferred** — a mechanism the numbers are consistent with and that no control
  here isolated. Say so in the same paragraph, not in a footnote.
- **Not established** — what the previous sentence might have tempted a reader
  to conclude, written down so it cannot be read in by accident.

Four rules follow from that ladder and are worth stating separately.

**A unit test is not a measurement.** A number whose only support is an
assertion describes the implementation, not the machine: it does not enter the
ladder at **Measured**. The boundary equality across five slice sizes is a unit
result — the runs cover four settings, of which three are traced.

**A matched pair is matched in time as well.** Two arms compared at different
points in a session are not a pair, however self-consistent each one is.

**Do not promote a claim by rewording it.** "Can cause" does not become "caused"
because the sentence reads better. If the causal chain was not established,
the weaker verb is the accurate one.

**Do not delete a limitation to make a page shorter.** A limitation may be moved
to where it is needed rather than repeated in every paragraph, but it does not
get cut. Equally, it does not lead: the finding comes first.

## Provenance beats tidiness

**Never rename an experiment directory, a dataset path, or a published URL** to
match a change in wording. Every existing reference — articles, the portfolio
page, other people's links — reaches this work through those names.
`exp-002-speculative-decoding-economics` keeps its directory name although
nothing in prose is called "economics" any more. That is the intended outcome,
not an oversight.

Reader-facing titles and prose are free to change. Paths are not.

## Data

Everything in `data/` carries provenance and a row count in `data/README.md`.
Nothing there is smoothed, interpolated, or back-generated. Figures are
regenerated by the plot scripts, which read only `data/`; a figure is never
hand-edited, and a number never appears in prose without appearing in `data/`
first.

Every metric in a run record is nullable. An unmeasured quantity is `null`,
never `0` — a zero is a measurement.

## Workloads

`workloads/generator.py` builds every synthetic prompt from a seed, and the
harness never writes one to disk. So the shapes and the config YAMLs are
tracked and the prompts are not, and EXP-001 — real agent sessions rather than
generated ones — has no `config/`. Reproducing it means reproducing the
phenomenon, not replaying the bytes; `docs/reproducibility.md` says what that
needs.

## Before anything is committed

`DATA_POLICY.md` governs, and this repository is public. It forbids, among other
things, absolute machine paths, hostnames, LAN addresses, credentials, and
verbatim captures of anyone else's prompt or model output. The last one cannot
be rotated away: removing it means rewriting every commit that carries it, so
search history by content and not only by path.

Machine-specific operational detail — where each repository lives, how the
article site is deployed — is deliberately not in this repository, for the same
reason.

## Tests

    uv run pytest

`ruff` is run ad hoc with `uvx ruff check` and is not a dependency or a gate.
The repository carries no ruff configuration, so its defaults apply and a few
findings predate any given change — fix what you touched, and leave the rest
rather than folding an unrelated cleanup into a research commit.

The harness parser has regression tests because it once silently dropped every
telemetry line of a whole run: the served build printed a field the regex did
not expect, and the failure mode was zero records rather than an error. Any
parser change gets a test with a real line from a real build.
